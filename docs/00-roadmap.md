# 🗺️ ۰۰ — نقشهٔ راه: چطور Rust را درست یاد بگیریم

## این پروژه چطور کار می‌کند؟

سه لایه دارد و هر لایه یک کار می‌کند:

```text
      ┌──────────────────────────────────────────────────────┐
      │  src/demos/  ← 🎓 آموزش: هر مفهوم را اجرا می‌کند     │
      ├──────────────────────────────────────────────────────┤
      │  src/*.rs    ← 🏗️ پروژه: کد واقعی و کارکننده        │
      ├──────────────────────────────────────────────────────┤
      │  docs/       ← 📚 مرجع: توضیح ریزبه‌ریز هر موضوع      │
      └──────────────────────────────────────────────────────┘
```

بهترین روش استفاده:
1. `cargo run -- demo <موضوع>` را اجرا کن و **خروجی را ببین**.
2. همان فایل را در `src/demos/` باز کن و کامنت‌ها را بخوان.
3. برای عمق بیشتر، مستند متناظر در `docs/` را بخوان.
4. کد را **عوض کن** و ببین چه خطایی می‌گیری — بهترین معلم، خطای کامپایلر است.

## پنج اصل یادگیری Rust

### ۱. با کامپایلر بحث نکن، ازش بپرس
خطای کامپایلر Rust **بهترین معلم دنیا** است: می‌گوید چه شد، چرا شد، و
اغلب **دقیقاً می‌گوید چه بنویسی**. مثال واقعی از این پروژه:

```text
error[E0502]: cannot borrow `data` as mutable because it is also borrowed as immutable
 --> src/demos/ownership.rs:132:5
  |
13|     let r = &data;      // قرض ثابت شروع می‌شود
  |             ----- immutable borrow occurs here
14|     println!("{}", r.len());
15|     data.push(4);        // ❌
  |     ^^^^^^^^^^^^ mutable borrow occurs here
```
کافی است `r` را قبل از `push` ببندی — یا در Rust مدرن، اصلاً کاری نکنی
(چون قرض با **آخرین استفاده** تمام می‌شود، نه با انتهای بلوک).

### ۲. اول «چرا»، بعد «چطور»
مثلاً قبل از اینکه `Rc<RefCell<T>>` را حفظ کنی، بپرس: «چرا Rust اجازه نمی‌دهد
دو تا `&mut` داشته باشم؟» جواب: چون **دادهٔ رقابتی** و **اشاره‌گر آویزان**
منشأ بیشتر باگ‌های C++ است. حالا `Rc<RefCell>` دیگر «تزیین» نیست، یک ابزار
آگاهانه است که هزینه‌اش (پنیک زمان اجرا) را می‌شناسی.

### ۳. «تنبل» باش: استاندارد را ترجیح بده
حداقل تا ماه دوم، پروژه‌هایت را **بدون crate** بنویس. جدول:
`Vec`, `HashMap`, `BTreeMap`, `VecDeque`, `BinaryHeap`, `HashSet`,
`Rc`, `Arc`, `Mutex`, `RwLock`, `RefCell`, `Cell`, `Cow`, `PathBuf`,
`TcpListener`, `thread`, `mpsc`, `Duration`, `SystemTime`, `FromStr`…

همین پروژه ثابت می‌کند با همین‌ها می‌شود یک برنامهٔ کامل ساخت.

### ۴. تست را کنار کد بنویس، نه بعداً
در Rust این عادت را از روز اول بگیر:

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn add_and_list() {
        let mut a = App::open(Box::new(MemoryStore::new())).unwrap();
        let id = a.add("تست", Priority::Normal, vec![]).unwrap();
        assert_eq!(id, TaskId(1));
    }
}
```
فایل `src/app.rs` این پروژه ۹ تست دارد که همه در `cargo test` اجرا می‌شوند.

### ۵. کد را «کوچک و درست» نگه دار
Rust پاداش «طراحی ساده» را می‌دهد و مجازات «طراحی درهم» را. اگر گیر کردی،
اغلب جواب این است: **مالکیت داده را جابه‌جا کن، نه اینکه با `clone` و `Rc`
سرپوش بگذاری.**

## چک‌لیست تسلط (هر مورد را با کد ثابت کن)

- [ ] می‌توانم تفاوت `String` و `&str` را با مثال توضیح دهم
- [ ] می‌دانم چرا `let b = a;` روی `String` مالکیت را منتقل می‌کند ولی روی `i32`
      کپی می‌کند
- [ ] می‌توانم یک صفت (trait) با متد پیش‌فرض بنویسم و آن را برای دو نوع پیاده کنم
- [ ] می‌دانم عملگر `?` چه کاری می‌کند و `From` چه نقشی دارد
- [ ] می‌توانم یک ایتراتور دلخواه (`impl Iterator`) بنویسم و `size_hint` بدهم
- [ ] تفاوت `Fn`, `FnMut`, `FnOnce` را با کد نشان می‌دهم
- [ ] می‌توانم بین `Rc<RefCell<T>>` و `Arc<Mutex<T>>` انتخاب درست کنم و دلیلش را بگویم
- [ ] می‌دانم چرا `ThreadPool` نیاز به `Box<dyn FnOnce() + Send + 'static>` دارد
- [ ] می‌توانم یک `macro_rules!` با تکرار `$( )*` بنویسم
- [ ] می‌دانم `unsafe` **چه چیزی** را باز می‌کند (و چه چیزی را نه)
- [ ] می‌توانم «دام بایت/کاراکتر» در UTF-8 را با کد نشان دهم
- [ ] می‌دانم `thread::scope` چه مشکلی را حل می‌کند

## اگر گیر کردی

| مشکل | راه‌حل |
|------|-------|
| خطای `borrow of moved value` | مالکیت منتقل شده؛ `&` بده یا `clone` کن — [۰۳](03-ownership.md) |
| `cannot borrow as mutable` | دو قرض متضاد؛ دامنه را کوتاه کن — [۰۳](03-ownership.md) |
| `trait bound not satisfied` | قید (bound) لازم است — [۰۴](04-types-and-traits.md) |
| `dyn Trait cannot be sent` | `+ Send + Sync` لازم است — [۰۸](08-concurrency.md) |
| `lifetime may not live long enough` | عمر خروجی را صریح کن — [۰۳](03-ownership.md) §۵ |
| کامپایل کند است | `cargo build --timings`، تقسیم کریت به workspace — [۱۴](14-performance.md) |
| کنسول فارسی را به‌هم می‌ریزد | ترمینال با پشتیبانی RTL یا فایل خروجی بگیر — [۱۳](13-pitfalls.md) |

> 💡 **قانون آخر:** اگر یک ساعت گیر کردی، کد را ساده‌تر کن (نوع را عوض کن،
> مالکیت را جابه‌جا کن، یک لایه انتزاع بردار). در Rust، «رفتن به عقب» معمولاً
> سریع‌ترین راه جلو رفتن است.
