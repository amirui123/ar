# 🔐 ۰۳ — مالکیت، قرض‌گیری و عمر (قلب Rust)

> این سند مهم‌ترین سند همین پوشه است. اگر فقط یک چیز را عمیق یاد بگیری، همین باشد.

## چرا Rust مالکیت دارد؟

هر برنامه‌ای که حافظه را دستی مدیریت می‌کند، یکی از این دو مشکل را دارد:
* **C/C++:** فراموشی `free` (نشت) یا `free` دوباره یا استفاده بعد از آزادی → کرش/آسیب‌پذیری.
* **Java/Python/Go:** زباله‌روب (GC) → مصرف حافظهٔ بیشتر و «توقف‌های پیش‌بینی‌نشدنی».

Rust راه سوم را انتخاب کرد: **مالکیت در زمان کامپایل، آزادسازی قطعی در زمان اجرا،
بدون GC و بدون `free` دستی.**

---

## ۱) سه قانون مالکیت

1. هر مقدار یک **مالک** دارد.
2. در هر لحظه **فقط یک** مالک.
3. وقتی مالک از دامنه بیرون رفت، مقدار **رها (drop)** می‌شود.

```rust
{
    let s = String::from("سلام"); // s مالک بافر heap است
}                                  // اینجا drop(s) صدا زده می‌شود → حافظه آزاد
```

مثل C++ RAII است، ولی با این تفاوت که **استفادهٔ بعد از آزادسازی غیرممکن است**:

```rust
let s = String::from("x");
drop(s);
println!("{s}");   // ❌ error[E0382]: borrow of moved value
```

---

## ۲) انتقال (move) در برابر کپی (copy)

```rust
let a = String::from("سلام");
let b = a;              // مالکیت منتقل شد (move) — a دیگر معتبر نیست
println!("{b}");        // ✅

let x: i32 = 5;
let y = x;              // کپی (copy) — هر دو معتبر
println!("{x} {y}");    // ✅
```

### چرا این تفاوت؟ (نکتهٔ کلیدی)
`String` روی heap است و سه کلمه روی پشته دارد: اشاره‌گر، طول، ظرفیت.
اگر `let b = a;` «کپی سطحی» می‌کرد، دو مالک به یک بافر اشاره می‌کردند →
`drop` دوباره → خرابی. Rust این را **در زمان کامپایل** ممنوع کرد.

### کدام انواع `Copy` هستند؟
* همهٔ اعداد، `bool`, `char`, `&T` (مرجع!), `Option<i32>`, آرایه‌های انواع Copy.
* ❌ نه: `String`, `Vec<T>`, `Box<T>`, `HashMap`.

```rust
#[derive(Clone, Copy)]      // ⚠️ Copy نیاز به Clone دارد
struct Point { x: f32, y: f32 }
```
> 💡 `Copy` یعنی «کپی‌کردن ارزان و بدون اثر جانبی» — فقط روی انواع بدون
> «مالکیت منبع» (بدون heap، بدون فایل، بدون قفل) بگذار.

### `Clone` — کپی آگاهانه و صریح
```rust
let a = vec![1, 2, 3];
let b = a.clone();      // کپی کامل روی heap (گران!) — تو تصمیم گرفتی
```
🎯 ترفند: هر `clone()` فوری در کد **بوی بد طراحی** دارد. اول بپرس: «چرا
مالکیت را جابه‌جا نمی‌کنم؟» یا «چرا مرجع نمی‌دهم؟»

## ۳) قرض‌گیری (borrowing)

قرض = اشاره‌گر موقت بدون انتقال مالکیت.

```rust
fn len(s: &String) -> usize { s.len() }     // قرض ثابت
fn push(s: &mut String) { s.push('!'); }    // قرض تغییرپذیر

let mut text = String::from("سلام");
len(&text);          // چند قرض ثابت هم‌زمان اشکالی ندارد
push(&mut text);
```

### 📏 قانون طلایی قرض‌گیری
> در هر لحظه، **یا** یک قرض تغییرپذیر (`&mut`)، **یا** هر تعداد قرض ثابت (`&`).
> هرگز هر دو با هم.

```rust
let mut v = vec![1, 2, 3];
let r1 = &v;        // قرض ثابت
let r2 = &v;        // ✅ چند ثابت هم‌زمان OK
// let m = &mut v;  // ❌ تا وقتی r1/r2 زنده‌اند، ممنوع
println!("{r1:?} {r2:?}");
let m = &mut v;     // ✅ پس از آخرین استفادهٔ r1/r2 (NLL)
m.push(4);
```

**چرا؟** چون اگر هم‌زمان یکی بخواند و یکی بنویسد، یا یکی بنویسد و یکی بخواند،
racing data داری. Rust این را در زمان کامپایل غیرممکن می‌کند.

### Non-Lexical Lifetimes (NLL) — بهبود مهم Rust 2018
قرض با **آخرین استفاده** تمام می‌شود، نه با انتهای بلوک:

```rust
let mut v = vec![1];
let first = &v[0];
println!("{first}");     // آخرین استفاده از قرض اینجاست
v.push(2);               // ✅ قبل از Rust 2018 این خط خطا می‌داد
```

### مثال کلاسیک: چرا این خطا می‌گیریم؟
```rust
let mut v = vec![1, 2, 3];
let x = &v[0];           // قرض ثابت شروع
v.push(4);               // ❌ v.push ممکن است حافظه را جابه‌جا کند →
                         //    x به حافظهٔ آزادشده اشاره می‌کرد!
println!("{x}");
```
راه‌حل‌ها: `let x = v[0];` (کپی مقدار)، یا `println!` را قبل از `push` بیاور.

## ۴) مرجع در برابر مقدار در امضای تابع

| امضا | چه می‌گیرد | چه وقت |
|------|-----------|--------|
| `fn f(s: String)` | مالکیت | تابع می‌خواهد مصرف/نگه‌داری کند |
| `fn f(s: &str)` | قرض | ✅ پیش‌فرض درست — نسخهٔ اول انتخاب |
| `fn f(s: &String)` | قرض `String` | ⚠️ تقریباً هرگز؛ `&str` بهتر است |
| `fn f(s: &mut String)` | قرض تغییرپذیر | تابع می‌خواهد تغییر بدهد |
| `fn f(s: impl Into<String>)` | هر دو | کالر راحت (ارگونومی) |

```rust
fn shout(s: &str) -> String { s.to_uppercase() }

let owned = String::from("hi");
shout(&owned);       // &String → &str با Deref coercion ✅
shout("literal");    // &'static str ✅
```

> 🎯 **ترفند ارگونومی:** `title: impl Into<String>` هم `&str` و هم `String`
> را می‌پذیرد — فراخوان نه مجبور به `to_string()` می‌شود، نه ما مجبور به
> اضافه‌کردن کالر اضافه. (در `model.rs` ما از همین استفاده کرده‌ایم.)

## ۵) عمرها (lifetimes)

عمر = «این مرجع تا کجا معتبر است». در ۹۹٪ کد **نمی‌نویسی‌اش**.

### سه قاعدهٔ حذف عمر (elision)
1. هر ورودی مرجع، عمر مستقل خودش: `fn f(a: &str, b: &str)` → `<'a, 'b>`.
2. یک ورودی مرجع → خروجی همان عمر را دارد.
3. `&self` / `&mut self` → خروجی عمر `self` را دارد.

```rust
fn first(s: &str) -> &str { … }        // قاعدهٔ ۲ خودکار اعمال می‌شود
```

### کِی باید بنویسی؟
```rust
// ❌ کامپایل نمی‌شود: خروجی از کدام ورودی می‌آید؟
fn longest(a: &str, b: &str) -> &str { if a.len() > b.len() { a } else { b } }

// ✅ با صریح‌کردن: «خروجی به‌قدر کوتاه‌ترینِ دو ورودی زنده است»
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str { if a.len() > b.len() { a } else { b } }
```

### ساختاری که مرجع نگه می‌دارد
```rust
struct Line<'a> {
    number: usize,
    text: &'a str,      // «این ساختار مالک متن نیست، قرض‌گیر است»
}
impl<'a> Line<'a> {
    fn width(&self) -> usize { self.text.chars().count() }   // `'_` هم قبول است
}
```

### `'static`
* `'static` = «تا پایان عمر برنامه». رشته‌های ثابت متن برنامه این‌طورند.
* ⚠️ **اشتباه رایج:** `T: 'static` یعنی «هیچ مرجع کوتاه‌عمری *داخلش* نیست».
  `String` هم `'static` است (چون هیچ قرضی ندارد)! پس `T: 'static` با
  «این مقدار یک رشتهٔ ثابت است» فرق دارد.

```rust
let owned: String = "x".into();
let leaked: &'static str = Box::leak(owned.into_boxed_str()); // نشت عمدی
```

### چهار «راه فرار» از دردسر عمر
1. **مقدار مالک برگردان** (`String` به‌جای `&str`) — ساده‌ترین.
2. **شاخص (index) برگردان** نه مرجع.
3. **`Cow<'a, str>`** — یا قرض بده یا مالک شو (در مسیر رایج صفر تخصیص).
4. **داده را داخل ساختار نگه دار** (owned) به‌جای مرجع.

## ۶) رهاسازی (Drop) و RAII

```rust
struct Connection { id: u32 }

impl Drop for Connection {
    fn drop(&mut self) {
        println!("اتصال {} بسته شد", self.id);
    }
}

{
    let c = Connection { id: 1 };
}   // ← اینجا خودکار: «اتصال ۱ بسته شد»
```
موارد استفاده از `Drop`: بستن فایل/سوکت، آزادکردن قفل، لغو اشتراک، ثبت زمان.

### ترتیب رهاسازی
* متغیرها به **عکس ترتیب ساخت** (LIFO) رها می‌شوند.
* فیلدهای ساختار به ترتیب **اعلان** رها می‌شوند.
* 🎯 `let _ = x;` **فوراً** رها می‌کند، ولی `let _x = x;` تا انتهای بلوک نگه می‌دارد.
  (این تفاوت در نگه‌داری قفل‌ها حیاتی است!)
* 🎯 `std::mem::drop(x)` رهاسازی دستی و صریح.

⚠️ **هرگز در `Drop` پنیک نکن.** اگر هنگام بازگشایی پشته (بعد از یک پنیک دیگر)
`Drop` هم پنیک کند، فرایند می‌میرد. اگر لازم است کار خطاپذیر انجام دهی،
از الگوی «به تعویق انداختن» استفاده کن یا خطا را بی‌صدا لاگ کن.

## ۷) الگوهای عملی

### ا) تابعی که هم می‌خواند و هم می‌نویسد
```rust
fn bump(counter: &mut usize) -> usize { *counter += 1; *counter }
```

### ب) برگرداندن یکی از ورودی‌ها (بدون کپی)
```rust
fn pick<'a>(a: &'a str, b: &'a str, use_a: bool) -> &'a str {
    if use_a { a } else { b }
}
```

### ج) گرفتن مالکیت و برگرداندنش
```rust
fn normalize(mut s: String) -> String {   // مالکیت را می‌گیرد…
    s.make_ascii_uppercase();
    s                                      // …و برمی‌گرداند
}
```
(وقتی می‌خواهی API را از قرض‌دادن به «مصرف‌کردن» ارتقا بدهی، این الگو مفید است.)

### د) `std::mem` — ابزارهای جابه‌جایی
```rust
let mut o = Some(String::from("x"));
let taken = o.take();                     // مقدار را بردار، None بگذار
let old = std::mem::replace(&mut o, Some(String::from("y")));
let swapped = std::mem::swap(&mut a, &mut b);   // بدون کپی!
let size = std::mem::size_of::<Vec<u8>>();      // ۲۴ بایت (۳ کلمه)
```

### ه) الگوی «borrow در برابر clone» در حلقه‌ها
```rust
// ❌ گران: هر تکرار یک کپی از کل داده
for item in data.clone() { process(item); }

// ✅ قرض بده
for item in &data { process(item); }

// ✅ یا اگر مالکیت لازم است، بردار را مصرف کن
for item in data { process(item); }   // data دیگر قابل استفاده نیست
```

## ۸) جدول عیب‌یابی خطاهای مالکیت

| خطا | معنی | راه‌حل |
|-----|------|--------|
| `borrow of moved value` | مقدار منتقل شده، بعد استفاده‌اش کردی | مرجع بده، یا `clone`، یا ترتیب را درست کن |
| `cannot borrow as mutable` | قرض ثابت زنده است | دامنهٔ قرض را ببند (NLL) یا داده را جدا کن |
| `value does not live long enough` | مرجع از دادهٔ محلی بیشتر عمر می‌کند | مالکیت بده یا عمر را محدود کن |
| `cannot move out of … because it is borrowed` | هم‌زمان قرض و انتقال | اول قرض را تمام کن |
| `does not implement Copy` | `move` در حلقه/بستار | `&` بده یا `clone` یا `move` آگاهانه |
| `cannot return reference to local variable` | برگرداندن مرجع محلی | مقدار مالک برگردان (String/Vec) |
